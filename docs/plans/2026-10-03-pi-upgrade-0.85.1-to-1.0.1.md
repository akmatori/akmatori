Verdict: **compiles and tests clean, but one behaviour change needs a config fix before merge.**
pi 1.0 is the stable line after the 0.87 → 0.99 jump. The 0.86 and 0.87 releases carry breaking changes,
none of which touch an API the worker uses; 1.0.0 and 1.0.1 add nothing breaking for the SDK. The
scratch trial of the target versions builds with zero source changes and passes 429 / 429 tests. The real
change is in pi-subagents: since 0.71 a new session may start with a `subagents_enable` loader instead
of the `subagent` tool (F1). Akmatori's prompts call `subagent(...)` directly, so we must ship
`"toolActivation": "eager"`.

Also in scope: a correction to the previous upgrade (F2): `gpt-6-astra-pro` and `gpt-6-astra-fast` are not
OpenAI built-ins and must leave the OpenAI picker; and a catalog refresh (F3) because pi dropped several
ids we list, including NVIDIA Nemotron 3 Super, which NVIDIA no longer serves.

Do NOT target 0.74.0 for pi-subagents: on pi 1.0.0 its background children fail with
"does not provide @earendil-works/pi-agent-core/node" (fixed in 0.75.0). We use foreground children
only, but pin `^0.75.0` anyway.

## Findings

### F1 — pi-subagents lazy tool activation (MUST FIX: ship `toolActivation: "eager"`)

pi-subagents 0.71 hid the full `subagent` tool behind a small `subagents_enable` loader to save prompt
tokens in interactive use. 0.74 made it model-dependent (`toolActivation: "auto"`): a fresh session on a
model that can add tools mid-conversation starts with the loader, and `subagent` becomes active only
after the model calls `subagents_enable({})`, on the *next* request.

For Akmatori this is wrong in three ways: our Go prompt templates, `SKILL.md` files and `AGENTS.md`
instruct the model to call `subagent({...})` directly; every incident is a fresh session (no resume), so
the activation cost would be paid on every incident; and in our offline probe the default config left
`subagents_enable` active *alongside* `subagent`, which is an extra tool schema per request for nothing.

Fix: add `"toolActivation": "eager"` to `akmatori_data/extensions/subagent/config.json` (the file is
read from `<PI_CODING_AGENT_DIR>/extensions/subagent/config.json`, which the compose mount already
provides). Verified on 0.99.2 and 1.0.1: session then starts with exactly `subagent` + `bg_wait`.
Note the doc: an invalid value is a config error, not a fallback to the default. pi-subagents 0.75 extends
this: an invalid value for *any* config key now fails config loading instead of silently dropping
`authorityPolicy` / `permissions` / `toolBudget` — so a typo in our file would fail the extension load.
Add a loader-level check (step 3).

### F2 — Correction: `gpt-6-astra-pro` / `-fast` are not OpenAI built-ins (fix picker)

pi-ai's OpenAI catalog (0.85.1 through 1.0.1) contains only `gpt-6-astra`. `gpt-6-astra-pro` exists only
in the OpenRouter catalog (`openai/gpt-6-astra-pro`); `gpt-6-astra-fast` only in the Vercel AI Gateway
catalog. The previous upgrade added both to the **OpenAI** picker by mistake (found by a grep that hit
those third-party catalogs). On the `openai` provider they fall through `resolveModel()` to a synthesized
spec: the request may 404 at OpenAI and cost is reported as 0.

Fix: OpenAI picker → drop `gpt-6-astra-pro` and `gpt-6-astra-fast`; keep `gpt-6-astra`. The OpenRouter
entries `openai/gpt-6-astra` and `openai/gpt-6-astra-pro` are correct (confirmed against the live
OpenRouter model list on 2026-09-20). README OpenAI row → "GPT-6 Astra" without the variants.

Picker ids no longer in pi's catalog: `gemini-2.0-flash`, `gemini-3-pro-preview` (also the **Go default**
for Google in `internal/database/db.go:643`), and all four NVIDIA entries (`meta/llama-3.3-70b-instruct`

### F4 — `SessionManager` is now canonical for provider context (no work, but note)

0.87.0: assigning `session.agent.state.messages` no longer replaces future request history. The worker
never does this. Everything goes through `createAgentSession` + `sessionManager`, so no change. This is
also the foundation for `appendContextEdit()` (F9) and for real resume later.

### F5 — Compaction and context wins (free)

- 0.86.0: per-model `reserveTokens` / `keepRecentTokens` via `compaction.modelOverrides` (typed in
  `CompactionSettings`). Optional adoption: pass overrides through `SettingsManager.inMemory({...})` for
  on-prem models with small windows. Deferred until an operator hits it.
- 0.87.1: split-turn compaction summaries no longer refused by Claude Fable 5.1.
- 0.87.0: error retries and length/overflow recovery no longer keep abandoned model attempts in future
  context; `context` handlers can no longer drop the prompt and tool declarations.
- 0.86.0: agent-level retry backoff capped at `retry.maxAgentDelayMs` (60 s default). 0.99.2: unparseable
  `Retry-After` falls back to exponential backoff. 1.0.1: "Selected model is at capacity" errors are retried
  instead of ending the turn.
- 1.0.1: Anthropic tools added or redefined mid-conversation are defined inline, so a redefinition keeps
  the prompt cache. This makes the lazy-loader path cheaper, but F1 still stands: we want no loader at all.

### F6 — Prompt cache warming (evaluate, default off for us)

0.86.0 adds cost-aware cache warming (`cacheWarming: "off" | "streaming" | "idle"`). `streaming` keeps a
valuable prefix alive during long tool runs, which describes our `execute_script` and SSH batches. It
spends tokens to save tokens, so try it in the bench with Anthropic before enabling per install.

### F7 — Provider fixes across our list (free)

Anthropic: strict tool schemas with `minimum`/`maximum` now sent non-strict instead of failing (check
whether any `gateway_call` / `execute_script` TypeBox schema carried those keywords);
`compat.allowedFallbackModels` to disable server-side fallback; workload identity federation env vars;
copy-code login for headless hosts; 1M-context Sonnet 5.5 / Opus 5.5. Bedrock: Claude requests no longer
fail with "Invalid signature in thinking block" after the system prompt or tools changed; pricing tiers
above 272k input tokens. OpenAI-compatible: unknown Chat Completions endpoints no longer get strict
schemas unless advertised; model-level `samplingParams` no longer dropped by direct `stream()`/`complete()`
(this fixes the one-shot path for child processes on custom endpoints); Responses errors name the real
provider; llama.cpp streams without `output_index` end with an error instead of mixed-up tool calls.
Google / Vertex: unsupported thinking levels fixed. Cloudflare AI Gateway Claude ids fixed. Mistral,
Fireworks, OpenRouter, Baseten, Cerebras, Cloudflare 520, Azure peak-load retry classification.

### F8 — pi-subagents hygiene (free)

0.75: background children work on pi 1.0 again; invalid config fails loudly (see F1); `/subagent-cost`
counts every round of resumed workflow children; async runs reach `run-history.jsonl`. 0.74: children
follow the parent's project trust (before, a child in an untrusted workspace still loaded that workspace's
settings, skills and, for background children, extensions — this closes the prompt-injected
`workDir/.pi` hole our rule file describes); codemode scripts can no longer call `subagent`. 0.73: huge
workflow results capped at 200 KB / 5000 lines with the full text on disk; `failureKind` on failed runs.
0.72: TypeBox provided by pi (no manifest warning). 0.71: `worker` starts fresh instead of forking;
`pi-ai >= 0.86.1` required. 0.70.1: runtime-registered agents honour `defaultModel` / `defaultProvider`
/ `defaultThinking`.

### F9 — Optional adoptions, deferred

- **`appendContextEdit(entryId, null)`** (0.87): omit one message from future provider context without
  rewriting history. A cleaner replacement for our 4 KB file-dump preview of large tool results: keep the
  full result in the transcript for audit, drop it from the model's context after the agent has read it.
  Design together with the threshold review noted last time.
- **Codemode + tool exposure** (0.99, leaner in 1.0.0): built-in `codemode` tool runs model-written
  JavaScript in a QuickJS sandbox that calls pi's tools in parallel. This is what our `execute_script`
  does by hand under `node:vm` (which cannot interrupt a tight synchronous loop). Spike: register gateway
  tools with `namespace` + `exposure: "codemode"` via `createCodemodeExtension()` and let pi own the
  sandbox. pi-subagents ≥ 0.74 already keeps `subagent` out of scripts. Not for this upgrade. See the MCP
  assessment of 2026-09-30: keep the MCP Gateway; do not move MCP connections into the worker.
- **`tool_search` + `exposure: "deferred"`** (0.99): our `list_tools_for_tool_type` / `get_tool_detail`
  discovery could become native deferred tools. Same spike as codemode.
- **Virtual models** (0.99, experimental; pi-subagents 0.75 children can run on them): route each request
  to a physical model via an extension. Fits the multi-model bet (cheap model for recon subagents, strong
  model for the parent).
- **`SessionManager.inMemory()` restore** for Slack / proposal resume: unchanged from the last plan.
- Not applicable to the headless worker: Sign in with ChatGPT / Radius, Meta Muse provider, `/bug`,
  image generation, Nix flake, fullscreen-by-default TUI, tool renderers.

## Risks

- **R1 — `subagent` inactive on first call** (F1). If the config file is missing on an install (the compose
  mount is `./akmatori_data/extensions:/home/agent/.pi/agent/extensions:ro`; a fresh install without the
  directory gets the default `auto`), the first subagent call may fail or cost an extra turn. Mitigation:
  step 3 log line; consider baking the config into the image as a fallback if pi-subagents ever reads it
  from the extension directory.
- **R2 — pi-subagents ≥ 0.71 requires `pi-ai >= 0.86.1`; 0.74.0 is broken on pi 1.0.** Always bump both,
  and never pin pi-subagents 0.74.0 together with pi ≥ 1.0.0.
- **R3 — Anthropic strict-tool downgrade** (0.99.2): tools whose schema uses `minimum`/`maximum` are sent
  non-strict. Harmless, but check gateway tool schemas so we know which ones lost strict mode.
- **R4 — compiled extension package.** pi-subagents loads from `index.js` now, not `index.ts` via jiti.
  Verified in the loader probe; the Docker `cp -r node_modules/pi-subagents/.` step copies the whole package.
- **R5 — pi 1.0.1 removed `npm-shrinkwrap.json`.** Transitive dependencies of pi are now resolved by our
  lockfile, not pinned by pi. Our `package-lock.json` still pins them for the Docker build, but a future
  `npm install` can move them. Keep `npm ci` in the Dockerfile (it is) and review the lockfile diff on each
  bump. pi recommends its own installer for pinned installs; not applicable to an SDK consumer.
- **R6 — Model catalog churn.** Six picker ids and two Go defaults are no longer in pi's catalog (F3). They
  still run via the synthesized spec with cost 0, except Nemotron 3 Super which NVIDIA no longer serves.
