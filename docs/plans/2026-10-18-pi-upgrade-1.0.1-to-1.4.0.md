## Findings

### F1 — Subagent tool cost drops ~80 % (ADOPT: comes with the bump)

pi-subagents 0.77 rewrote the `subagent` description (5.7 K → 1.2 K chars, one rule stated once) and the
schema; `bg_wait` went the same way. 0.77 also stopped telling the parent to call `{action:"list"}` and
`{action:"models"}` before it delegates; an unknown agent or model name now fails with "did you mean".
Our prompts launch by name already, so we only gain.

Per incident with 15 parent requests this is ~70 K fewer input characters (~17 K tokens). With prompt
caching most of it is cache-read, but the first request and every cache miss pay full price.

Action: none beyond the bump. Measure in the bench (step 6).

### F2 — `bg_wait` and `contact_supervisor` are dead weight for us (ADOPT: small config)

We run children in the foreground (`asyncByDefault: false`), so the parent never needs `bg_wait`.
`contact_supervisor` is now declared on any session that has `subagent` (so a forked child reuses the
parent's cache); called by the parent it only returns an error. Together they cost ~1.4 K chars per request
and are two tools a weak model can call by mistake.

Checked: `"waitTool": false` in `config.json` loads without error, but `bg_wait` stays declared (the option
only makes calls return at once). pi-subagents has no option to hide `contact_supervisor` on the parent.

Action: remove both from the parent's active tools through pi's own tool selection (exclude list on the
session, or `setActiveTools` after create), then re-run the probe. The docs say pi-subagents respects
Pi's allowlist/exclusions. If a child launch then breaks, leave them. Do NOT remove `contact_supervisor`
from *child* sessions. Trade-off: the parent then no longer shares the tool set with a forked child, so a
fork misses the cache. We do not fork, so this does not matter.

### F3 — Better resilience for free (ADOPT: comes with the bump)

From the 1.1–1.3 changelogs, all automatic:
- Retry now triggers for `server_busy`, "The upstream provider returned an error", "Unable to forward
  upstream stream", "The service is temporarily unavailable" (also made the first compaction fail),
  Mistral `finish_reason: "error"`, and stalled Bedrock HTTP/2 streams. Our `auto_retry_start` /
  `auto_retry_end` handlers already surface these in the incident log.
- Tool calls with malformed final JSON now fail validation and show the model its raw arguments.
  Before, `gateway_call` could run with only the fields parsed before the error (wrong tool args, silent).
- Invalid `\u` escapes in tool-call strings (e.g. `\usepackage`, Windows paths) no longer drop fields.
- Output token limit: input is estimated at 3.5 chars/token, fewer context-limit 400s.
- Anthropic: strict tool set rejected for size → one retry non-strict (we register many gateway tools).
- Anthropic/Bedrock: error tool results that contain images no longer cause a 400.
- `serializeConversation()` (compaction) omits thinking blocks, so a compaction request can no longer be
  larger than the context it summarizes.
- Model switch drops the old model's thinking blocks instead of sending them as text. No effect today:
  Akmatori does not resume sessions (every Slack / proposal turn is a fresh session).
- Session cost for tiered-price models (Haiku 5.5, Gemini 3.1 Pro, GPT-5.4) is no longer undercounted, so
  our `agent_runs` cost becomes correct for them.

Action: none. Add one test that a malformed-JSON `gateway_call` comes back as a validation error, not as a
gateway call (guards F3 against a future regression).

### F4 — Claude Haiku 5.5 for recon subagents (ADOPT: picker + default suggestion)

pi 1.1.0 adds `anthropic/claude-haiku-5-5`: 1 M context, $0.10 / $0.50 per M tokens (tier above 100 K
input), adaptive thinking up to `max`, cache lifetime declared (so cache warming works). It is about 50×
cheaper than Opus 5 and the right default for `runbook-searcher` / `memory-searcher`, which we can now
point at a cheaper model through the subagent model override (commit 11732e4).

Note: Haiku 5.5 has no `off` level in pi-ai 1.3.0 (`minimal` is unsupported too); the 1.3.0 changelog says
`off` was fixed for Haiku 5.5 and Opus 5. In the catalog `off` is now absent from the level map for both,
which means "use the default mapping". Verify in step 5 that `thinking: off` on Haiku 5.5 sends no
thinking block. If not, the UI must not offer `off` for it.

Action:
- Add `claude-haiku-5-5` to `llmModelSuggestions.ts` (Anthropic list and the subagent model list).
- Bench it as subagent model against Sonnet 5.5 for runbook/memory recall (see the bench project).

### F5 — Per-thinking-level sampling in `models.json` (EVALUATE: may simplify `sampling.ts`)

pi 1.0.2 adds `samplingParamsByThinkingLevel` in `models.json` for OpenAI-compatible APIs. We already
write `samplingParams` into the managed `models.json` entry and map params per API in `sampling.ts` via
`onPayload`. The new key helps only if operators want different `temperature` per thinking level, which
no one asked for. Child processes read `models.json`, so if we ever need it, the path is already there.

Action: none now. Note in the rule file.

### F6 — Codemode spike fixes (ADOPT: comes with the bump; re-run spike bench)

Our `AKMATORI_CODEMODE=1` spike gets: input constraints in tool declarations (1.2.0), elapsed time on the
codemode row, no quadratic join of `text()` output (seconds to minutes of blocked process before),
`// @options:` not on line 1 is an error instead of silently dropping `timeout_ms`, a two-worker cap
across sessions with cancelled workers counted until exit (1.3.0, prevents worker pile-up on repeated
timeouts), `tools.read()` returns image blocks (1.0.4), and unawaited `searchTools()` fixed (1.1.0).
pi-subagents 0.78: codemode no longer breaks the prompt cache on each resume.

The two-worker cap is global per process. One agent-worker serves many incidents in parallel. On 1.3.0 a
third concurrent script failed at once; 1.4.0 makes it wait up to 60 s for a free worker, and
`PI_CODEMODE_MAX_WORKERS` raises the cap.

Action: re-run the codemode spike bench on 1.4.0. Load check with ≥ 3 parallel incidents with scripts; if
scripts wait, set `PI_CODEMODE_MAX_WORKERS` in the worker env (Dockerfile / compose), sized to the worker's
CPU and memory.

### F7 — `agent_settled.aborted` (OPTIONAL: low value)

pi 1.1.0 adds `aborted` to `agent_settled`. Today the orchestrator sends "Execution cancelled" itself when it
handles `cancel_incident` and calls `session.abort()`; the runner does not handle `agent_settled`. pi's flag
would let the run log say "aborted" from pi's own view, for example when an abort comes from somewhere
other than `cancel_incident`.

Action: only if cheap while touching the event switch: log `event.aborted` on `agent_settled`.

### F8 — `pi-telemetry` hook (DEFER: spike only)

pi-ai 1.3.0 `StreamOptions` accepts `telemetryContext` (contract from `@earendil-works/pi-telemetry`: spans,
no exporter, no network calls). An OpenTelemetry adapter would give per-LLM-request spans inside our
incident traces. The changelog does not document it yet and the session-level API does not pass it, so wait
until pi exposes it on `createAgentSession`. No privacy risk from the new package itself: it sends nothing.

### F9 — pi-subagents launch path (CHECK, keep our env var)

0.79.1: apps that embed Pi now launch children with the app's own Pi install first;
`PI_SUBAGENTS_PI_CODING_AGENT_PACKAGE_ROOT` still has priority. Our Dockerfile sets it (fix 09cd906), so
behaviour does not change. Keep the env var: it is explicit and survives future lookup changes. If the
chosen install is broken, a launch now fails with the reason instead of a generic error.

0.79.1 also fixes "permission denied" on read-only installs. Our extension copy at
`/opt/pi-extensions/pi-subagents` is owned by `agent`, so no change, but this allows a read-only copy later.

`/share` destinations, OSC 52 clipboard, OSC 7501 program status, TUI/keybinding/theme fixes, Nix,

## Delta 1.3.0 → 1.4.0 (added 2026-10-22)

pi 1.4.0 and pi-subagents 0.79.2 / 0.80.0 / 0.81.0 add no break for us and some useful fixes:

### F11 — Session and compaction robustness (ADOPT: comes with the bump)

- **Truncated tool call recovery** (1.4.0): after a response was cut off at the output limit, pi dropped the
  cut tool call but kept its tool results, and the provider then rejected *every* later request. An
  incident that hit the output limit mid-tool-call was dead from that point. Now fixed.
- **Compaction summaries use the model's output limit** (1.4.0) instead of a fixed cap. With reasoning
  models, compaction failed with "generation hit the token cap". Long incidents compact more reliably.
- **Whitespace-only tool output** (for example a bare `\r\n` from `bash`) made OpenAI Completions,
  OpenAI Responses and Google requests fail with a 400 (1.4.0). Now fixed.
- **More retries** (1.4.0): more gateway upstream failures, `stream disconnected before completion`
  from Codex-style proxies, transient Vertex OAuth refresh failures. Also no false "retryable" match on
  digits inside request ids.
- **OpenAI Responses** keeps the prompt cache when a tool is removed (1.4.0). Relevant to F2 if we drop
  tools after session create.
- **`grep` tool runs `rg --no-config`** (1.4.0). An operator `RIPGREP_CONFIG_PATH` can no longer change
  the recon subagents' search results.

Action: none. In the bench, check that no incident fails with "token cap" during compaction.

### F12 — `MiniMax-M3.1-Flash` (ADOPT: picker)

pi 1.4.0 adds `minimax/MiniMax-M3.1-Flash`: 1 M context, $0.15 / $0.60 per M tokens (half the price of
`MiniMax-M3`), thinking low to max. It is the cheap subagent model for MiniMax users, the same role as
Haiku 5.5 for Anthropic (F4). The `forceAdaptiveThinking` merge in `resolveModel()` keys on the
provider (`ADAPTIVE_THINKING_REQUIRED_PROVIDERS`), not on the model id, so the Flash id is covered.

### F10 — `enableSlashCommands: false` (ADOPT: one config line)

pi-subagents 0.80.0. We delegate only through the model, never through `/run` or other pi-subagents slash
commands. The option keeps the `subagent` tool and drops all slash commands. Fewer moving parts in a
headless worker. Verify with the probe that the tool list is unchanged.

### pi-subagents 0.80 / 0.81 items that do not apply

`parallel` / `tasks` / `chain` children with their own `cwd` and `model` (we launch single named agents;
per-agent models already come from `agentOverrides`), `<pi_subagents_notice>` wrapping (async only),
`outputSchema` retry turn (our agents use no `outputSchema`), FleetView mouse, Windows startup fixes,
steering fixes, completion notices kept across restarts (async only). Package size grows 6.8 → 10.8 MB
unpacked; the Dockerfile copies it twice (`node_modules` and `/opt/pi-extensions`), so the image grows
by about 8 MB.

### F13 — Fresh installs: subagents never worked (FIXED on this branch)

Not caused by the upgrade, found by it. On any install whose `agent_sessions` volume was created by an
image without `/home/agent/.pi/agent`, the worker cannot write the child `settings.json` and child `pi`
cannot open `auth.json`, so every subagent launch fails and the parent silently falls back. Fix: the
Dockerfile creates `~/.pi/agent/{agents,extensions}` owned by `agent`; `childConfigWriteWarning()` logs the
one-time `chown` for volumes that already have the root-owned dir. Before deploying anywhere, check:
`docker exec akmatori-agent ls -ld /home/agent/.pi/agent` (must be `agent agent`).

### F14 — Compose-only installs ran subagents async (FIXED on this branch)

Found by the SRE Bench A/B. `"asyncByDefault": false` (and `toolActivation`, `enableSlashCommands`)
live in `akmatori_data/extensions/subagent/config.json`, but release installs download only
`docker-compose.yml` and `nginx.conf`, so they never had that file and pi-subagents ran its defaults:
`subagent` calls are async and the tool loads lazily (`subagents_enable`). With `bg_wait` excluded (F2) and
no wake-up for an SDK session, a weak parent launched the searchers and ended its turn ("the runbook search
is running in the background"): Claude Haiku 5.5 did this on most bench incidents; Sonnet and DeepSeek
polled `status` and went on. Fix: the `init-dirs` service writes the same JSON when the file is missing
(never overwrites an operator's copy), the worker warns when the config does not set
`asyncByDefault: false`, and a worker test keeps the compose JSON and the repo file in sync. The first
seed used `printf '%s\n'`: Compose drops that backslash inside the double-quoted command, so the file
got a trailing `n` and was invalid; it now uses `echo`, checked with `docker compose config` + alpine.
