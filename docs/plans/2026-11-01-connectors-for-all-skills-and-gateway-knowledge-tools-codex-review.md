# Codex review of the 2026-11-01 connectors + knowledge-tools plan

Reviewer: Codex CLI 0.164.0, model gpt-6-astra, reasoning high, read-only sandbox. Run 2026-11-01 against main 6fe75f0.
Plan: 2026-11-01-connectors-for-all-skills-and-gateway-knowledge-tools.md

Read the plan in full and checked the implementation and repository rules. No files were modified. I would resolve the high-severity findings before implementation.

## Factual errors

1. **[high] The skill mapping does enforce authorization today.** It does not isolate individual skills, but it determines the incident-wide set of authorized instances. `GetToolAllowlist` excludes instances absent from enabled non-system skills, and the gateway rejects calls outside that list. “Enforces nothing” understates a real authorization expansion. Sources: `internal/services/skill_service.go:256`, `internal/services/skill_service.go:270`, `mcp-gateway/internal/mcp/server.go:301`, `mcp-gateway/internal/auth/authorizer.go:108`.

2. **[high] B1.2 does not “mirror `MemoryService.validate` exactly.”** Current validation rejects descriptions over **500 bytes**, rejects empty descriptions, and uses **`MemoryBodyMaxBytes`**, not the nonexistent `MemoryBodyMaxLen`. `NormalizeMemoryType` preserves unknown values so validation rejects them; only file ingestion converts unknown types to `fact`. Existing validation neither reserves `file-` nor requires a scope to correspond to an existing skill. The proposed rules are a mixture of existing behavior and new policy. Sources: `internal/services/memory_service.go:310`, `internal/services/memory_types.go:44`, `internal/services/memory_types.go:61`, `internal/services/memory_service.go:1022`. Also, `draftDescription` truncates at a UTF-8-safe **byte** boundary, not a word boundary: `internal/services/memory_drafter.go:153`.

3. **[high] Exporting memories does not preserve un-ingested disk edits.** `ExportZip` queries the database; it never reads the memory directory. B1 already replaces ingestion with DB-to-disk synchronization, so un-ingested edits can be overwritten **before B2 ships**. The “export first, loses nothing” assurance is incorrect. Sources: `internal/services/memory_export.go:15`, `internal/services/memory_service.go:420`, `internal/services/memory_service.go:1237`; plan: `docs/plans/2026-11-01-connectors-for-all-skills-and-gateway-knowledge-tools.md:379` and `:431`.

4. **[medium] The gateway already has `Runbook` and `Memory` mirror models, in a different file.** Extend or relocate the existing types; declaring new versions in `db.go` would duplicate them. The same file contains the gateway’s `CronJob.Tools` and `CronJobTool`, which A2 misses. Sources: `mcp-gateway/internal/database/models_proposals.go:35`, `:48`, `:64`, `:80`.

5. **[medium] The SQLite claims are wrong.** SQLite rejects both `ILIKE` and `DROP TABLE IF EXISTS skill_tools, cron_job_tools`; I confirmed both with an in-memory SQLite connection. Existing dead-column migrations execute `ALTER TABLE … DROP COLUMN`, not table rebuilds. The cited cron migration test uses SQLite, not a PostgreSQL test matrix. Sources: plan `docs/plans/2026-11-01-connectors-for-all-skills-and-gateway-knowledge-tools.md:165`, `:255`, `:373`; `internal/database/db.go:372`, `:432`; `internal/database/models_cron_test.go:140`. Existing portable gateway search uses `LOWER(...) LIKE`: `mcp-gateway/internal/tools/events/events.go:117`.

6. **[medium] The caller/lifecycle inventory is incomplete.** There are **four** production callers using `GetToolAllowlist`, including the omitted API request path at `internal/handlers/api_incidents.go:499`. Ingestion runs after every `FinishRun`, including request and cron work—not only incident completion. Sources: `internal/handlers/alert_processor.go:755`, `:997`, `internal/handlers/slack_processor.go:272`, `internal/services/incident_service.go:792`, `:812`.

7. **[low] B2’s description of manifest parity is incomplete.** Fifty feedback entries is an initial reservation, not an absolute maximum: unused fact capacity goes back to feedback. Rendering also enforces independent byte and line caps. Preserve these behaviors, not just “150 entries, feedback first.” Sources: `internal/services/memory_service.go:1136`, `:1158`, `:1166`, `:1191`.

## Design risks

1. **[high] Setting every system cron’s `tools_enabled=false` breaks the improvement evaluator.** It requires `incidents` and `proposals`, but the proposed disabled allowlist contains only events, then events/runbooks/memory. Existing system crons also preserve operator-edited tool assignments; forcibly setting all system rows false discards that intent. Define infrastructure access separately from required built-ins. Sources: `internal/database/db.go:1085`, `:1195`, `:1205`, `:1234`; `internal/services/cron_runner.go:685`.

2. **[high] `gorm:"default:true"` can silently undo an explicit `ToolsEnabled=false`.** This exact issue is already handled for `Enabled` and `PostResults` by explicit updates inside the create transaction. Apply the same treatment or choose a representation without that ambiguity. Keep update requests as `*bool`: omitted means unchanged, false means disabled. Test create-false, both seed paths, and unrelated partial updates. Sources: `internal/services/cron_runner.go:827`, `:840`, `:850`; `internal/handlers/api_cron_jobs.go:130`; `internal/database/db.go:1159`.

3. **[high] “All enabled instances” grants more than connector access.** Enabled `incidents` and `proposals` instances are seeded automatically, while the Connectors catalog hides them. A therefore grants incident reads and proposal operations to ordinary investigations even when no connector changed. The claim that operators can inspect all enabled tools on Connectors is incomplete. Also, calls without an instance select the first authorized instance; broadening and reordering the list can change the selected environment. Sources: `internal/services/tool_service.go:194`, `:217`; `internal/services/connector_catalog.go:82`; `mcp-gateway/internal/mcp/server.go:339`. Specify built-in policy and deterministic instance selection.

4. **[high] `connected-tools` needs discovery, import, and formatting handling—not merely a reserved directory.** The enabled-skill list comes from DB rows, and the worker filters discovered skills against that list, so the new non-DB skill disappears whenever the filter is active. Filesystem import would conversely create a DB row unless explicitly excluded. Reading the file also sets `last_skill=connected-tools`, replacing the domain skill used by formatting rules. Sources: `internal/services/skill_service.go:231`; `agent-worker/src/agent-runner.ts:1498`; `internal/services/skill_file_sync.go:267`, `:301`; `agent-worker/src/agent-runner.ts:1648`; `internal/services/formatting_rule_matcher.go:91`. Include an upgrade collision policy for an existing user skill with that name.

5. **[high] Operator-memory protection must be atomic and must define what counts as operator-owned.** A preliminary SELECT followed by an unconditional upsert/delete permits a concurrent operator edit to be overwritten. Put the ownership condition in the mutation itself. Existing upsert preserves `created_by` but still replaces content; additionally, approving an update to an agent memory passes `created_by=operator` through an upsert that does **not** update authorship. Such an approved memory can remain eligible for subsequent agent modification. Sources: `internal/services/memory_service.go:951`, `:953`; `internal/services/proposal_service.go:367`. Add concurrency tests and decide how approved edits and legacy empty authorship are protected.

6. **[medium] Reserving `file-` does not protect context-file summaries.** Summaries have `created_by=agent`, and an operator rename is preserved during subsequent summarization. A renamed summary can therefore pass the prefix check; delete has no stated prefix restriction at all. Define write/delete policy using `source_file_id`, and never let gateway upserts clear that field. Sources: `internal/services/memory_source_files.go:18`, `:24`, `:49`; `internal/database/models_context.go:58`.

7. **[high] `X-Incident-ID` identifies a scope, not a run.** Follow-up turns reuse scopes. Copying the events counter would implement a quota per scope, not per run; its wholesale map reset and process restart also reset quotas. The gateway currently receives no run ID header. Derive provenance from the actual `AgentRun.IncidentUUID`, and define missing, stale, superseded, and request-scope handling. Prefer passing `run_id` and validating its scope before mutations. Sources: `internal/database/models_agent_runs.go:29`, `:35`, `:54`; `internal/handlers/agent_ws.go:133`; `agent-worker/src/gateway-client.ts:356`; `mcp-gateway/internal/tools/events/events.go:235`, `:249`. Test repeated Slack turns, API requests, cron ticks, and superseded runs—not just incident versus cron.

8. **[medium] A constants-comparison test does not establish validation parity.** It misses trimming, empty-field handling, unknown types, UTF-8 truncation, scope rules, and preservation of description overflow. Truncating `description` does not itself place the discarded text into `body`. Use shared behavioral fixtures across modules or a small shared validation package, with explicitly documented agent-only differences. Sources: `internal/services/memory_service.go:310`, `:719`; `internal/services/memory_drafter.go:153`; plan `docs/plans/2026-11-01-connectors-for-all-skills-and-gateway-knowledge-tools.md:281`.

9. **[medium] The memory-generation gate needs a precise compatibility contract.** The mirrored field must remain nullable: nil means enabled. Preserve the distinction between agent writes and operator writes, including uploads and approved proposals. Also acknowledge the timing change: today the gate is checked during end-of-run ingestion; the proposal checks each immediate DB mutation, so turning it off before completion no longer discards earlier writes from that run. Sources: `internal/database/models_settings.go:311`, `:355`; `internal/services/memory_service.go:287`, `:616`; `.claude/rules/memory-and-runbooks.md:65`, `:79`. Test nil, missing row, read error, false, mid-run toggles, and continued operator writes.

10. **[high] Search cannot replace maintenance enumeration as specified.** Dreaming needs to enumerate global memories updated within 14 days and find duplicates. A required lexical query, zero-match exclusion, maximum 20 results, and no pagination/date filter cannot reliably traverse that corpus. The evaluator also requests recent feedback. Add a bounded listing/recent mode or cursor-based enumeration rather than relying on a “broad” query. Sources: `internal/database/db.go:1065`, `:1067`, `:1195`; plan `docs/plans/2026-11-01-connectors-for-all-skills-and-gateway-knowledge-tools.md:249`, `:276`.

11. **[medium] The large-corpus search algorithm is underspecified and can reduce recall abruptly.** Choosing the rarest terms requires document-frequency information before prefiltering; the plan provides no index or statistics cache. Zero-frequency alert IDs can consume the rare-term budget. Restricting candidates to ten terms can exclude documents that match other retained query terms, changing rankings at 2,001 rows. Specify corpus statistics, positive-frequency selection, wildcard escaping, deterministic ID tie-breaking, and memory/time bounds. Test both sides of the threshold and concurrent updates. Source: plan `docs/plans/2026-11-01-connectors-for-all-skills-and-gateway-knowledge-tools.md:245`. Also use model-specific projections: runbooks have `title/content`, and memory search promises `created_by`, absent from the proposed SELECT (`internal/database/models_context.go:41`, `:61`).

12. **[high] The migration needs an explicit add/backfill/drop transaction and restart guard.** Pre-migrations execute before AutoMigrate, so the backfill cannot assume `tools_enabled` exists. Retrying after mappings are removed must not reset operator-selected booleans. Cover fresh installs, direct upgrades, partially migrated schemas, repeated startup, disabled assignments, and system cron customization on both databases. Sources: `internal/database/db.go:108`, `:160`; plan `docs/plans/2026-11-01-connectors-for-all-skills-and-gateway-knowledge-tools.md:163`. Dropping the mappings also makes rollback lossy; document that operationally.

13. **[high] B1’s completion sync does not keep all prompts fresh.** Gateway writes bypass the API handler that regenerates affected skill files. Completion sync updates disk manifests, but existing SKILL.md files still embed their previous manifests. B2’s DB renderer does not fix that unless those files are regenerated or cease embedding mutable memory. Global AGENTS.md and scoped SKILL.md therefore have different freshness behavior. Sources: `internal/handlers/api_memories.go:395`; `internal/services/skill_file_sync.go:317`; `internal/services/skill_prompt_service.go:194`, `:339`. Prefer DB-backed per-run rendering or an explicit invalidation path.

14. **[medium] Worker cleanup must preserve shared runtime code and `agentDir` behavior.** The parent already bypasses `models.json` (`modelsPath:null`), but `runtimeProviderId`, custom-provider registration, adaptive-thinking configuration, and credential scrubbing still serve the parent; `resolveModel` is also imported by one-shot calls. The resource loader still uses `agentDir`, and its SDK implementation creates a disk-backed settings manager when none is supplied. Sources: `agent-worker/src/agent-runner.ts:387`, `:447`, `:527`, `:553`, `:1359`, `:1404`, `:1481`, `:1536`; `agent-worker/src/oneshot-llm.ts:20`; `agent-worker/node_modules/@earendil-works/pi-coding-agent/dist/core/resource-loader.js:244`. Preserve directory ownership, operator-extension loading, and generic extension-error logging. The Dockerfile’s cited 57–119 range also contains production dependency installation, compiled-code copy, and `USER agent`, not just subagent setup (`agent-worker/Dockerfile:69`, `:74`, `:100`, `:107`).

15. **[medium] B2 must change memory-reference semantics.** Current `ResolveRefs` returns `/akmatori/memory/<scope>/<name>.md` for memory links. Keeping it unchanged returns dead paths after removing the mount. Return memory IDs/scope/name for `memory.get`; retain filesystem paths only for context files. Resolving file existence also requires a gateway `ContextFile` mirror/query, absent from B1’s model inventory. Sources: `internal/services/memory_refs.go:98`, `:103`, `:122`; `internal/database/models_context.go:13`.

## Omissions

1. **[high] Proposal cron creation, snapshots, validation, and pending proposals need migration.** The API applies `tool_logical_names` through `CreateJob`/`CronJobUpdate`; staleness checks compare assigned tools. The gateway preloads `Tools` for snapshots and cron listings. Dropping join tables without changing these paths breaks proposal creation/review/application. Decide how existing `proposed_content` and `current_snapshot` JSON are translated. Sources: `internal/services/proposal_service.go:288`, `:378`; `mcp-gateway/internal/tools/proposals/proposals.go:130`, `:191`, `:594`; `mcp-gateway/internal/database/models_proposals.go:64`.

2. **[high] Persisted system-cron prompts are missing from the upgrade strategy.** Dreaming and improvement-evaluator prompts contain subagent names and disk paths, and their seeds deliberately preserve existing rows. Updating constants will not update installed jobs. The startup warning scans skills/runbooks/memories but omits cron prompts; `DefaultProposalEditorPrompt` also references memory-writer. Sources: `internal/database/db.go:1007`, `:1065`, `:1130`, `:1195`, `:1213`. Migrate only recognized old defaults, preserve custom prompts, and warn about remaining cron references.

3. **[high] API-side namespace reservation and existing namespace collisions are omitted.** Adding `memory`/`runbooks` only to gateway maps leaves the API accepting conflicting HTTP connectors and MCP servers. Existing connectors with those names would then be skipped by gateway loading. Update both reservation lists and define an upgrade collision policy. Sources: `internal/services/http_connector_service.go:10`, `internal/services/mcp_server_service.go:93`, `mcp-gateway/internal/tools/registry.go:255`, `:268`. Explicitly decide whether new built-ins receive seeded instances and catalog hiding, matching the existing pattern (`internal/services/tool_service.go:194`, `internal/services/connector_catalog.go:82`).

4. **[medium] B2 misses remaining callers and reusable tests.** `memory_source_files.go` still calls `SyncMemoryFiles`; `MemoryIngester` and its setter live in `skill_service.go`, not only `incident_service.go`. Deleting the entire sync test file would also delete useful manifest line/byte-cap and feedback-budget tests. Existing MCP examples only direct dynamic discovery, so reusing the renderer does not supply every MCP parameter schema as A3 promises. Sources: `agent-worker/src/gateway-tools.ts:135`, `:143`; `internal/services/skill_prompt_service.go:869`. Add real gateway/worker coverage for discovery, authorization, failed writes, large tool-result handling, and fresh/persisted-volume startup. ## Suggested changes

1. **[high] Resolve the authorization policy before A1.** Specify infrastructure instances, built-in capabilities, proposal-chat restrictions, and tools-disabled cron behavior separately. Preserve explicit instance routing and fail-closed lookup errors. This avoids accidentally granting proposal operations everywhere while removing them from their intended evaluator. Sources: `internal/services/proposal_service.go:505`, `internal/database/db.go:1205`, `mcp-gateway/internal/auth/authorizer.go:107`.

2. **[high] Move DB manifest rendering and prompt freshness into B1; leave physical disk cleanup for B2.** This makes gateway writes immediately usable without a temporary completion-sync design. Change the worker’s memory mount to read-only during the transition if retained, and arrange backup/reconciliation of disk-only edits before the first DB-authoritative sync. Sources: `internal/services/skill_prompt_service.go:339`, `internal/handlers/api_memories.go:395`, `docker-compose.yml:194`, `internal/services/memory_export.go:15`.

3. **[high] Separate storage-contract tests from search-quality tests, and gate removal on both.** First establish atomic ownership protection, provenance, nullable gate behavior, idempotency, and PostgreSQL/SQLite upgrade coverage. Then evaluate retrieval with realistic corpora and maintenance enumeration. Do not remove subagents until custom-provider, one-shot, operator-extension, and persistent-volume smoke tests pass. Sources: `internal/services/memory_service.go:951`, `internal/database/models_agent_runs.go:54`, `internal/database/models_settings.go:316`, `agent-worker/src/agent-runner.ts:1359`, `:1481`.

4. **[medium] Make release coordination explicit.** A and B1 change DB schema, API contracts, prompts, gateway registration, and worker capabilities together. Specify supported component-version combinations, draining of active runs, rollback/backup requirements, and handling of persisted old cron prompts and pending proposals. Keep obsolete request fields rejected as planned, but retain migration fixtures and compatibility tests. Sources: `docker-compose.yml:120`, `:158`, `:207`; `internal/handlers/agent_ws.go:785`; `internal/database/db.go:1130`; `internal/services/proposal_service.go:378`.
