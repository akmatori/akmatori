## Findings

### F1 — pi-subagents now fails closed on model/provider mismatch (must test on staging)

- 0.50.0: rejects configured subagent models that are not in the active host model registry before spawning.
- 0.55.0: fails a child launch when the child reports a different provider/model than the resolved
  requested model.
- 0.65.0: model selection fails clearly when configured models are unavailable instead of using a
  provider default.

This is exactly the class of bug fixed in `2761deb` (one provider id for parent and child,
`runtimeProviderId()` → `akmatori-custom`). The fix should already satisfy the new checks: the parent
registers the provider on the `ModelRuntime` (`ensureProviderAuthResolvable`) and materializes the same
id in `<agentDir>/models.json` + `settings.json`. But the new checks are stricter than 0.45.1, so run the
provider matrix in step 4 before merge. Diagnostic inside the container:
`pi auth check --model akmatori-custom/<model-id>`.

Helpful in the same area: 0.52.0 "trust the running parent session model when no model is configured,
so gateway and proxy parent models can launch children outside the host registry".

### F2 — `subagent_wait` removed, `bg_wait` added (no work)

0.61.0 removed the deprecated wait alias. Akmatori prompts, skills, agent definitions and Go code never
reference either tool. Nothing to change.

### F3 — Children no longer inherit the operator's global context (verify, likely no work)

0.58.0: agents omit the operator's global context file by default; `inheritGlobalContext: true`
restores it. 0.65.0: foreground children no longer load ambient extensions.

Akmatori's three built-in agents (`runbook-searcher`, `memory-searcher`, `memory-writer`) declare only
`tools:` and carry all inputs in the task string (scope, incident UUID, alert text). They need no
extensions and no global context. Confirm on staging that `memory-writer` still finds
`/akmatori/memory/<scope>/` from its task body alone.

### F4 — Compaction is materially better for our workload (free win)

- 0.84.4: large tool results that cross the auto-compaction threshold are compacted between tool
  execution and the next assistant response, instead of being sent to the provider first. Our
  `gateway_call` / `execute_script` outputs are the main source of oversized turns.
- 0.84.3: threshold auto-compaction no longer skipped when the provider omits streaming usage data
  (on-prem OpenAI-compatible endpoints often do).
- 0.84.3/0.84.4/0.85.0: summaries no longer expose tools or force `toolChoice: "none"`; truncated
  summaries are not persisted; branch summaries no longer fail when reasoning consumes the old
  2048-token output cap.
- 0.84.3: new `session_compact_failed` extension event with reason, retry state, source, error (F9).

### F5 — Proxy fixes land exactly where deployments behind Squid hurt (free win)

- 0.85.0: `NO_PROXY` matching fixed for root domains and subdomains.
- 0.85.0: proxied plain-HTTP provider requests no longer hang after a tool call (tunneled with CONNECT).
- 0.84.4: Google Vertex `HttpsProxyAgent is not a constructor` under HTTP(S) proxy fixed.
- pi-subagents 0.65.1: proxy environment variables honored in detached background runs.

`proxy.ts` sets `HTTP_PROXY`/`HTTPS_PROXY`/`NO_PROXY` and a global undici dispatcher; these fixes apply
on top without code changes. Re-test the `llm_enabled` proxy path on a proxied install.

### F6 — Anthropic thinking and refusal handling (free win, one optional field)

- 0.85.0: per-turn thinking effort is preserved; safe recovery from signed-thinking mismatches.
- 0.84.4: `supportsMidConvoEffort` on custom Anthropic Messages model compat settings.
- 0.84.3: automatic server-side refusal fallback for first-party models, priced with the returned model.
- pi-subagents 0.67.0: forked child keeps its requested thinking level (needs pi ≥ 0.85.0).

Optional adoption: when the `custom` provider uses the Anthropic Messages API, write
`compat.supportsMidConvoEffort: true` on the managed `akmatori-custom` entry in `models.json`
(same place we already write `forceAdaptiveThinking`).

### F7 — Multi-provider fixes that cover our provider list (free win)

OpenAI-compatible: `toolChoice` honored with no tools; `reasoning_details` replay preserved and merged;
thinking signatures no longer serialized repeatedly; `supportsMaxOutputTokens`, `vllmPriority`, and
thinking-token budget fields for vLLM / SGLang / llama.cpp. Mistral: fragmented tool calls; native HTTP
stream instead of SDK. DeepSeek: output limit sent in the right field; V4 Flash Vision (experimental).
Google / Vertex: output-limit and provider-error stops no longer treated as tool use;
`thinkingLevelMap` honored on custom models. Bedrock: redacted reasoning replay; empty-key tool args.
OpenRouter: no `effort: "none"` for reasoning-mandatory models. Kimi: cached tokens counted as cache
reads. Fireworks GLM adapter fixed. GPT-5.6+ Responses prompt cache uses `prompt_cache_options.ttl`.

### F8 — New models (small code change)

pi-ai 0.85.1 ships `gpt-6-astra`, `gpt-6-astra-fast`, `gpt-6-astra-pro` for OpenAI API keys.
Add them to `web/src/components/settings/llmModelSuggestions.ts` above the gpt-5.6 trio, same pattern
as the 0.84.1 upgrade. `deepseek-v4-flash-vision-exp` is experimental; skip.

### F9 — `session_compact_failed` event (small code change)

`agent-runner.ts` handles `compaction_start` / `compaction_end` (with `aborted`, `errorMessage`,
`willRetry`). 0.84.3 adds `session_compact_failed` with `reason`, retry state, `source`, error message.
Add a case that writes a `📦 Context compaction failed (<reason>)` line to the incident output and log,
so operators see why an investigation degraded instead of a silent retry loop.

### F10 — Delegated child usage now appears in `subagent` tool results (medium code change)

pi-subagents 0.59.0: "Include delegated child usage in subagent tool results and `/subagent-cost`".
Today `tokens_used` / `cost_usd` on `agent_runs` exclude every subagent child process (rule file:
"subagent child processes remain untracked"). On `tool_execution_end` for `toolName === "subagent"`,
parse the usage block from the result and add it to `usageTotals`. Confirm the exact result shape on
staging before writing the parser; keep it tolerant (missing block → no change).

### F11 — Startup and hygiene fixes (free win)

- 0.84.3: failed extension factories no longer leave event subscriptions / provider registrations active.
- 0.84.3: UTF-8 BOM no longer breaks frontmatter and settings files (operator-authored skills).
- 0.84.3: `README.md` / `AGENTS.md` inside skill directories no longer reported as broken skills.
- 0.84.3: writes to `auth.json` / `models-store.json` keep administrator-managed permissions.
- 0.84.4: resumed sessions no longer corrupt the next entry when the JSONL lacks a trailing newline.
- 0.84.3: adapters send pi's default `User-Agent` unless overridden (watch corporate gateways that
  allowlist UAs; see Risks).

### F12 — Optional adoptions, deliberately deferred to follow-ups

- **`SessionManager.inMemory()` restorable entries (0.85.0).** Lets us keep session entries in
  Postgres instead of workspace JSONL and restore them into a fresh worker. This is the missing piece for
  real resume in Slack / proposal chat (CLAUDE.md: "session resume is NOT used") and for surviving
  worker restarts. Separate design.
- **`defaultTools` setting (0.84.2).** Per-project or global built-in tool selection. Could back an
  operator-facing "read-only investigation" mode (no `edit` / `write`). Note the 0.84.2 fix: it keeps
  SDK `customTools` when selecting built-ins.
- **`PI_EXPERIMENTAL=1` strict JSON-schema constrained sampling** for `read` / `bash` / `edit` /
  `write` (0.84.2). Could cut malformed tool calls from weaker on-prem models. Try in akmatori-bench
  first, not in production.
- **pi-subagents model fallback:** `fallbackModels`, `subagents.defaultProvider`,
  `subagents.maxThinking`, global `timeoutMs`, watchdog launch rules (0.64), 429 read-only continuation
  (0.66). Fits the multi-model bet; needs a settings surface in the API/UI.
- `ui_prompt_start` / `ui_prompt_end`, RPC `clear_queue`, PowerShell tool, TUI changes: not applicable
  to the headless worker.

- **R3 — children lose global context by default** (F3). Low: our agents carry inputs in the task string.

  may reject requests. Low; only affects installs that filter by UA.
- **R5 — Anthropic refusal fallback switches model silently** (0.84.3). Cost is priced on the returned
  model; a transcript notice appears only when cache-miss notices are enabled. Low.

### Not done (deliberate)

- **F9 `session_compact_failed`: no work.** It is an *extension* event (`SessionCompactFailedEvent` in
  `extensions/types.d.ts`), not an `AgentSessionEvent`. Our `session.subscribe` handler already
  receives `compaction_end` with `aborted`, `errorMessage`, `willRetry` and prints them, which is the
  same information on the session stream.
- **F6 `supportsMidConvoEffort`: not set.** The flag asserts that "the exact model transport supports
  effort-only system messages and thinking binding controls". That is true for first-party Anthropic
  models (already built in) but unknown for an arbitrary `custom` Anthropic-Messages endpoint; setting it
  blind would trade a working request for a 400. Revisit if an operator runs a first-party-compatible
  gateway and asks for mid-conversation effort changes.
- **Step 4 staging matrix** (anthropic, openai on gpt-6-astra, custom OpenAI-compatible, custom
  Anthropic-Messages; one incident each; subagent calls succeed; `tokens_used` includes child usage;
  proxied install) requires a container with live providers and was not run here. Run it before merge.
